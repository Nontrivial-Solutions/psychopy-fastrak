## Context and Problem Statement

Based on [ADR 00001](./00001_architecture.md) and [ADR 00002](./00002_documentation.md) we will be
leveraging existing deign and omitting normal documentation levels. Due to lacking PsychoPy
development and system docs the development of the plugin will still require some reverse
engineering. This ADR decides how to document that reverse engineering.

## Decision Outcome

We will use blog style development notes where relevant. This will allow flexibility in style and
quick turn around.

Drivers not considered.
