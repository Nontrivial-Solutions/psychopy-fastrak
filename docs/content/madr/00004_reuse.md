## Context and Problem Statement

The PsychoPy experiment life cycle allows for [routines][DD_RTN] to be used more than once in an
experiment. Unfortunately, the architecture of PsychoPy does not encapsulate the routines in any
way. This means when this happens objects are duplicated and names are reused. This ADR decides how
we will handle the reuse of names and objects within one experiment flow.

## Decision Outcome

Add a reset to the state and reuse objects.  

Existence of objects will be checked and only created when not already existing locally. A "clear"
functionality will reset the object state at the end of a routine.

## Decision Drivers  

- Must be easy to understand the flow
- Must be easy to debug

## Considered Options

- Wrapper to maintain list of objects.  
- Add a reset to the state and reuse objects.  
- Constructor should reset object.  

### Wrapper to Maintain List of Objects

- Bad, because it's hard to understand the flow.  
- Bad, because it's hard to debug.  

### Add a Reset to the State and Reuse Objects

- Good, because it's easy to understand the flow.  
- Good, because it's easy to debug.  

### Constructor Should Reset Object

- Bad, because it's hard to understand the flow.  
- Bad, because it's hard to debug.
